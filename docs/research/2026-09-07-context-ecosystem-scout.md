## 1. Part A — context engineering: 10 adoptable ideas

1. **Treat KV-cache hit rate as the agent's #1 production metric.** Manus argues agent traffic is prefill-dominated (their input:output token ratio ≈ 100:1), so cached-prefix hit rate dominates both latency and cost; the practices: keep the prompt prefix byte-stable (no per-request timestamps up front), make context append-only, serialize deterministically (JSON key order), and mark cache breakpoints explicitly. DevAgent's fixed-offset splice (`src/prompt.ts:470-472`) already implements "stable prefix, volatile tail"; the missing half is *measurement*: record cache-read vs cache-write token ratio per worker turn from provider usage fields (cost_in_usd ticks from FR-GROK-03 already land in the ledger) and alert on regressions → **context/workers**. [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
2. **Mask, don't remove — tool availability without tool churn.** Manus: dynamically adding/removing tool definitions invalidates the KV-cache for everything after the definitions and produces hallucinated actions against no-longer-defined tools; instead use a context-aware state machine with consistent tool-name prefixes and constrained selection. DevAgent phase-gates work with G1-G4; the adoption is: one static tool schema per worker run, phase constraints expressed in the prompt/state machine — never mid-run toolset swaps on the LeanKG/MCP surface → **workers/orchestrator**. [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
3. **Errors are context for the next turn — compact, don't delete.** 12-factor-agents factor 9 ("compact errors"): keep structured error context across turns instead of raw dumps or silent truncation. DevAgent's resilience classes (provider 503, ALL_TARGETS_SKIPPED, gate exit codes) currently live in run logs; a compact, stable error taxonomy injected into the retry prompt generalizes the Q27 retry-memory pattern → **resilience/workers**. [humanlayer/12-factor-agents](https://github.com/humanlayer/12-factor-agents)
4. **Own your prompts and context window; the ledger is the reducer state.** 12-factor factors 2/3/12 ("own your prompts", "own your context window", "stateless reducer"): agent state should be a deterministic fold over the event stream, not hidden framework state. DevAgent's ledger JSONL is exactly this fold source — a reducer that reconstructs any loop/worker context from the ledger enables resume-after-compaction and replay without persisting prompts → **selfbuild/orchestrator**. [humanlayer/12-factor-agents](https://github.com/humanlayer/12-factor-agents)
5. **Context rot ⇒ smallest high-signal token set; system prompts at the "right altitude".** Anthropic: accuracy degrades as context grows (n² attention, attention budget), so curate the minimal informative context; system prompts should sit between brittle hardcoded if-else logic and vague shared-assumption prompts. DevAgent audit item: keep the worker system prompt at policy altitude (gate contracts), push repo-specific detail into digests → **context**. [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
6. **Just-in-time retrieval + progressive disclosure over pre-fetch.** Anthropic (and Claude Code's own design): maintain lightweight identifiers (file paths, stored queries) and load data at runtime; metadata — names, sizes, timestamps — steers exploration. DevAgent's LeanKG digest should emit pointers (symbol → file:line) rather than inline code the worker then re-fetches — inlining burns the attention budget twice → **context**. [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
7. **Compaction and tool-result clearing as budgeted primitives.** Anthropic's context-editing API clears the oldest tool results past a configurable threshold with a `clear_at_least` floor so each cache invalidation pays for itself; thinking-block clearing documents the cache trade-off explicitly. OpenAI is productizing the same shape in the Codex CLI: experimental `features.context_management.experimental_mode` activates token-budget context, history notes, and a `new_context` tool (PR #42385), plus "Preserve Guardian review evidence across compaction" (PR #41879). DevAgent: long selfbuild loops accumulate worklog/tool streams in worktrees; a threshold-triggered compaction pass writing a durable marker (the COMPACT_CONTEXT_MARKER pattern) bounds child-worker context without touching the ledger → **selfbuild**. [Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [Codex changelog](https://learn.chatgpt.com/docs/changelog)
8. **Sub-agent digests work, but two hops is the documented ceiling.** Manus's widely cited follow-on caveat is that each sub-agent hop compresses unless the sub-agent returns a full transcript; Anthropic recommends sub-agent architectures for parallel research with digest-style returns, and lists their trade-offs against compaction and note-taking in the same post. DevAgent's childTrails digest is the digest-return pattern already; the guardrail: digest final outcomes + evidence pointers, never intermediate tool output → **context**. [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); exact Manus wording sits in the fetched page's truncated middle [INFERENCE].
9. **Structured note-taking as cross-session memory.** Anthropic's conclusion: note-taking excels "for iterative development with clear milestones" — exactly a selfbuild loop's shape. DevAgent's lessons digest is roll-up only; a per-task one-line run note (tried / gate outcome / artifact path) that feeds the next task's trail is a thin extension of the existing trail ledger → **lessons**. [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
10. **Triggers and human contact as canonical context surfaces.** 12-factor factors 7/11 ("contact humans with tools", "trigger from anywhere"): external events and ask/human-answer flows should enter context in one bounded, canonical form. DevAgent already has ask/human-answer and evidenceGaps; the PRD §20 dispatch sheet is where multi-channel triggers normalize into the same event shape → **product**. [humanlayer/12-factor-agents](https://github.com/humanlayer/12-factor-agents)

### "The harness is the product" (2026 essays)

Dave Beckett (2026-03-06, nine months hands-on with the major harnesses): "the model is the engine; the harness is the car" — below the frontier, models converge fast enough that harness quality dominates UX; the agentic loop is mostly `observe repo → plan → edit → run tests → inspect → iterate`; "the IDE is becoming the operating system for AI agents"; open-source harnesses run roughly three months ahead of commercial polish; and the model picker disappears into automatic routing (cheap/reasoning/coding/verifier per task class). DevAgent embodies the thesis (a selfbuild loop iterating on its own harness); the two adoptable points are (1) **router-by-task-class** behind the WorkerAdapter seam — Cursor's Auto modes and Factory Router commercialized exactly this in 2026, DevAgent's per-role model config + preflight is the seam — and (2) harness moats come from *state* (ledger, lessons, KG digests), not model choice → **workers/product**. [Dave Beckett](https://www.dajobe.org/blog/2026/03/06/harness-is-the-product/)

## 3. White space — what none of them do that DevAgent does or could

1. **Loop-level context substrate.** Every competitor manages context per session/PR: Cursor's in-repo hooks, Codex's session compaction, Jules's AGENTS.md. None ship cross-task, cross-iteration memory with measured impact: DevAgent's lessons digest + eval-guard ranking (Q39) and the childTrails ledger have no counterpart; nobody even exposes fleet-level compaction state to operators. [Cloud Agents docs](https://cursor.com/docs/cloud-agent), [Codex changelog](https://learn.chatgpt.com/docs/changelog)
2. **Domain-specific validation depth.** The competitor frontier is generic: CI fixer (Jules), code/secret/dependency scans (Copilot), security review + automated QA (Factory), AI PR review (Devin). No one approaches G2 migration-safety, G3 FK-integrity, G4 async/race review, or G5 STRIDE threat modeling; the 2026 self-review wave (Copilot reviewing its own diff pre-PR) validates the direction but stays surface-level. [Jules changelog](https://jules.google/docs/changelog), [Copilot update](https://github.blog/ai-and-ml/github-copilot/whats-new-with-github-copilot-coding-agent/), [Factory news](https://factory.ai/news?category=product) [INFERENCE: depth judged from marketing pages, not hands-on]
3. **Outcome-priced, agent-measured economics.** Pricing everywhere is quota/credits (Kiro credits, Copilot AI credits, Devin credits) — usage meters, not value meters. Cognition's AI Productivity Guarantee is the only outcome-pricing signal, and it is computed by a vendor estimator outside the agent for enterprise contracts. DevAgent's ledger could compute cost-per-verified-merge per iteration and steer per-run budgets in-band — the caps already exist; the value metric does not. [Kiro pricing](https://kiro.dev/pricing/), [Copilot plans](https://docs.github.com/en/copilot/get-started/plans), [Cognition](https://cognition.com/blog/ai-guarantee)
4. **Cache-aware orchestration as a first-class, reported feature.** Cursor bills cache reads explicitly and Manus treats hit rate as the top metric, but no vendor exposes cache behavior in agent run reporting or documents fixed-offset prompt assembly. DevAgent's COMPACT_CONTEXT_MARKER splice could become a measured, reported property (cache-hit ratio per worker turn) before anyone else ships it. [Cursor pricing](https://cursor.com/docs/models-and-pricing.md), [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) [INFERENCE: competitor prompt internals are private]
