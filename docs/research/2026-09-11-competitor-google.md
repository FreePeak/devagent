# Google's async/agentic dev stack — automatic dev-workflow anatomy (2026-09-11)

Scope: how Google's products mechanically implement "assign a task → plan → execute → validate → PR" — Jules, Gemini CLI (+ its GitHub Actions), Antigravity, Gemini Code Assist's agent surfaces, and the Firebase Studio exit. Method: primary sources read directly on 2026-09-11 — `jules.google/docs` (via its llms.txt index), the `google-gemini/gemini-cli` GitHub repo docs, `antigravity.google/docs` (llms.txt index), Google developer blogs, one arXiv paper. Complements, does not restate, `docs/research/competitor-agents-probe.md` (Devin/OpenHands) and the 2026-09-07 scout set. Every status claim is dated; anything not confirmable from a live page is marked [unverified].

## Google Jules

**What it is / status (2026-09)**
- Asynchronous coding agent (Google Labs), launched 2025-05-19, out of beta 2025-08-06 (the FAQ still self-describes "Public Beta" — docs lag). Async means: submit a task, Jules runs in a fresh cloud VM, you get a summary + diff + branch/PR.
- GitHub-only source binding ("In the future, Jules will work with more version control systems" — docs/tasks-repos). No deploy story of its own (see Render integration below).
- Model era (official changelog): Gemini 2.5 Pro at GA → Gemini 3 Pro (2025-11-19, Ultra first) → **Gemini 3 Flash as base model on all tiers (2026-01-30)** → **Gemini 3.1 Pro default for Pro plan (2026-03-09, replacing Gemini 3 Pro)**. Free tier advertised as "Gemini 2.5 Pro" on the homepage — homepage trails the docs.
- Plans (docs/usage-limits, 2026-09): free = 15 tasks / rolling 24h, 3 concurrent; Jules in Pro (Google AI Pro) = 100/day, 15 concurrent; Jules in Ultra = 300/day, 60 concurrent. Paid tiers only via **@gmail.com** Google AI subscriptions; enterprise/Workspace users get an interest form — no org tier yet. Community note: the free daily cap was **cut from 60 to 15** at the 2025-08 GA (HN 44813854).
- No published SWE-Bench-style task benchmark for Jules itself; Google's claims are the 9.5% failure-rate reduction from the Planning Critic (2026-01-26) and the June 2026 proactive-agent eval paper (below).

**Trigger surfaces**
1. Web UI: repo selector + branch + prompt; optional image attachments (≤5MB, PNG/JPEG, task creation only).
2. GitHub issue label `jules` (case-insensitive) — requires the Jules GitHub App; Jules comments on the issue and posts a PR link when done (2025-06-26).
3. PR review comments on Jules-authored PRs (stage 8 below).
4. Jules Tools CLI (`npm i -g @google/jules`): `jules remote new --repo X --session "…"` (+`--parallel N`, max 5 same-prompt tasks), `remote list`, `remote pull` (apply WIP code locally without waiting for a GitHub push), repo inference from cwd, TUI dashboard with side-by-side diffs (2025-10-02, updated 2025-11-10).
5. REST API `https://jules.googleapis.com/v1alpha` (alpha, x-goog-api-key; max 3 keys/account, keys auto-disabled if leaked publicly): `sources` (read-only list of bound repos), `sessions`, `activities`; RPCs `:sendMessage`, `:approvePlan`; `automationMode: AUTO_CREATE_PR`; `requirePlanApproval: true/false` (docs/api/reference).
6. Scheduled Tasks (2025-12-10): recurring tasks on Daily/Weekly cadences from the task input; **Edit/Pause/Resume added 2026-01-26** (docs/scheduled-tasks still says editing is unsupported — docs lag the changelog). Templates exist for performance/design/security maintenance personas.
7. Suggested Tasks / "Proactivity" toggle per repo (2025-12-10): Jules scans the repo and proposes plans for resolvable `#TODO`s; performance-optimization detection added 2026-01-26; max 5 repos; periodic suggestion emails; paid users get **auto-solving of the top-confidence suggested task** (2026-01-26).
8. Curated MCP integrations (2026-02-02): **allow-listed servers only** — Linear, Stitch, Neon, Tinybird, Context7, Supabase — API-key auth in Settings; Google's stated rationale is vetting data flow + tool permissions for a cloud agent with GitHub access. Contrast: Jules is the only agent in this cluster that refuses arbitrary MCP.
9. Render integration (2025-12-10): Jules detects failed Render builds/deployments on its own PRs, analyzes logs, pushes fixes.

**Workflow pipeline (stage by stage)**
1. **Bind**: connect the Jules GitHub App; grant all or selected repos. Repo-level config attaches: setup script, env vars, memory, proactivity toggle.
2. **Provision VM**: fresh, short-lived Ubuntu VM per task (20GB disk since 2025-08-15). Jules clones the repo, then either infers setup from the repo/AGENTS.md/README or runs the user's **setup script** (discrete commands only — long-running servers like `npm run dev` are explicitly unsupported, FAQ). Preinstalled toolchain is unusually complete and current (docs/environment): pyenv+Python 3.12, pip/pipx/poetry/uv/pytest/ruff/mypy/black, Node 18/20/22 via nvm + npm/yarn/pnpm/bun, Java 21 + Maven + Gradle, Go 1.24, Rust 1.87, clang/gcc/cmake/ninja/conan, **Docker + Docker Compose 28.2**, ChromeDriver, git/jq/rg/tmux. Playwright added to the base image 2025-08-07.
3. **Environment snapshot** (2025-08-05): "Run and Snapshot" validates the setup script and stores a VM snapshot reused by all future tasks in that repo — cold-start amortization.
4. **Plan** (session state `PLANNING`): Jules reads AGENTS.md, produces a natural-language plan with steps + assumptions; Interactive Plan mode (2025-08-08) makes it ask clarifying questions first. If it needs input, state becomes `AWAITING_USER_FEEDBACK`.
5. **Plan gate** (state `AWAITING_PLAN_APPROVAL`): user expands steps, comments, approves. Two important auto-approval mechanics: (a) in the UI, navigating away **auto-approves the plan on a timer** ("no need to babysit" — docs/review-plan); (b) via the API, **plans are auto-approved by default**; `requirePlanApproval: true` opts into the gate. Since 2026-01-26 every auto-approved plan is reviewed by a second agent, the **Planning Critic**, before execution (claimed −9.5% task failures). Separately, a **Critic Agent** (2025-08-08, improved 2025-09-03 with visible step-by-step reasoning in the UI) does adversarial in-generation review of proposed changes — "critic-augmented generation."
6. **Execute** (`IN_PROGRESS`): Jules edits code in the VM. UI: activity feed (per-step completion, inline explanations, mini-diffs) + full diff editor (stacked diffs since 2025-09-04) + exportable WIP at any time (2025-08-15). Steering: mid-task chat feedback, pause/resume, file selector. API: immutable **activities** (event-source pattern — replayable, cacheable, `createTime` cursor since 2026-01-26) of types `planGenerated`, `planApproved`, `userMessaged`, `agentMessaged`, `progressUpdated`, with artifacts: `changeSet` (git patch + baseCommitId + suggested commit message), `bashOutput` (command/stdout/exitCode), `media` (base64 screenshots).
7. **Validate in-VM**: Jules writes and runs tests itself (bashOutput artifacts carry exit codes — machine-checkable evidence), can run web apps and return screenshots ("verify its work and it'll render the website and send you back a screenshot", 2025-08-07), and does web research for docs/code snippets (2025-08-08). Failure semantics (docs/errors): automatic retries on transient failures, then the task is marked failed + notification; rerun from the summary. Sessions via API end in `COMPLETED`/`FAILED` states.
8. **Deliver**: task summary (files changed, runtime, LOC delta) → **Publish Branch** (user owns the branch, Jules is commit author) or **Publish PR** (2025-08-04; API `AUTO_CREATE_PR`). Commit authorship configurable since 2026-02-19: Jules / co-authored (either order) / user-only — applied user-level across scheduled, suggested, and manual tasks (contribution-graph control).
9. **Review/repair loop**: Jules watches its PRs — reacts 👀 to review comments and pushes fix commits; **Reactive Mode** restricts it to `@Jules` mentions (2025-09-23). **CI Fixer** (2026-02-19): when a GitHub Actions check fails on a Jules PR, Jules receives the error, fixes, commits, resubmits — closed loop, no manual log pasting. **Render fixer** (2025-12-10) does the same for failed deploys, Jules-created PRs only. These are the only external feedback-ingest paths; there is no generic webhook API for arbitrary CI [inference from full changelog coverage].
10. **Remember**: repo-scoped **Memory** (2025-09-30) saves preferences/nudges/corrections for reuse in similar tasks; toggle under repo settings → "Knowledge". Plus AGENTS.md ingestion at every stage.

**Isolation & sandbox**
- One fresh cloud VM per task; full internet access — the FAQ is explicit: treat it as a hostile shared compute surface, don't commit secrets, audit dependencies. No documented network allowlist, egress policy, or user-visible isolation tech (gVisor/qemu [unverified]). Snapshot reuse is the only state carry-over. Env vars are repo-level, opt-in per task, frozen for the task's duration. No training on private repos (FAQ).

**Human gates & approval UX**
- Exactly two gates: the plan gate (which auto-approves on timer or by API default, with the Planning Critic as the compensating control) and the PR merge (always human). Browser notifications when a plan is ready or a task finishes. PR-comment actions gated by mention in Reactive Mode. Suggested Tasks add a dashboard approval step; Scheduled Tasks have none.

**Cost model / metering**
- Task-count quotas per rolling 24h + concurrency caps; hard stop (new-task button disabled) with upsell CTA; family-shared plans do not pool limits. No token metering or per-task cost telemetry is exposed. Model tier access is the real paywall. Queue prioritization teased as a future paid differentiator (usage-limits FAQ). API: max 3 keys, 429 on quota.

**What it can't do (mechanically)**
- No deploy control (only log-driven fix loops), no DB provisioning beyond env vars/Neon/Supabase MCP, GitHub-only, no long-running processes, no arbitrary MCP servers, no interactive shell, no org/SSO tier yet.
- HN-thread evidence (2025-08, HN 44813854) of operational gaps DevAgent should not copy: env state not persisting across feedback turns (a configured `bun` "vanishing" between turns and being reinstalled per step), premature completion, approval-state confusion, monorepo `cd` confusion, and refusal-to-publish-branch incidents; several heavy users ranked it below Codex/Copilot-agent for quality. The plan/timer auto-approval + critic is exactly the fix pattern for these.

**What DevAgent can learn or steal**
- Auto-approve + Planning Critic is a validated pattern for a headless loop that cannot wait for a human: cheap adversarial plan review instead of a blocking gate (vendor-claimed −9.5% failures; single source).
- Immutable, event-sourced activity log with a `createTime` cursor = the API-shaped version of DevAgent's "evidence attached per PR"; steal the cursor pattern for the TUI live feed instead of re-reading logs.
- Environment snapshots to kill worker cold-start (directly relevant to DevAgent's Compose boot cost per iteration).
- CI Fixer: DevAgent should subscribe to its own PRs' check failures and re-dispatch a repair iteration automatically — otherwise Jules looks more autonomous on red CI.
- Commit-authorship modes (co-authored/user-only): trivial, high-trust polish for evidence bundles.
- Task-count quotas + concurrency caps as a user-facing "agent budget" (simpler mental model than tokens); pairs with DevAgent's starvation/breaker ops.
- Moat intact: no migration-safety/shadow-DB gates, no FK/async domain review, no per-run evidence bundle, GitHub-only, single-agent-per-task (parallelism = N independent tasks, no scout/worker/reviewer roles), cloud-VM only, no BYO model.

## Gemini CLI (open source) + Gemini CLI GitHub Actions

**What it is / status (2026-09)**
- Apache-2.0 terminal agent (github.com/google-gemini/gemini-cli). **v0.59.0 stable released 2026-09-08** (nightly + preview channels; very high cadence). Gemini 3 Pro/Flash and 3.1 Pro Preview selectable via `/model`; docs/get-started/gemini-3 documents daily-limit exhaustion UX ("switch to Gemini 2.5 Pro, upgrade, or stop", with reset notices).
- Gemini Code Assist's IDE "Agent Mode" (VS Code Preview, IntelliJ stable) is **powered by Gemini CLI** embedded in the IDE (developers.googleblog 2025-08-21) — so Gemini CLI is the substrate, not just a peer product.

**Workflow pipeline (as an execution substrate)**
1. **Plan Mode** (default-on; `--approval-mode=plan`, `/plan`, Shift+Tab rotation Default→Auto-Edit→Plan): read-only research → `ask_user` clarifications → writes the implementation plan as a **Markdown file in a plans directory** → waits for confirmation before code. YOLO mode (`--approval-mode=yolo`) disables gates entirely.
2. **Execute**: tool loop (shell, file tools, web-fetch/search, MCP); plan artifacts, todos/tracker/planning tools (docs/tools/*); GEMINI.md hierarchical context; gemini-ignore; auto-memory.
3. **Validate / self-repair**: 
   - **Checkpointing** (settings-only since the CLI flag was removed in v0.11.0): before every file-mutating tool call it snapshots the project into a **shadow git repo** at `~/.gemini/history/<project_hash>` + saves conversation + the pending tool call; `/restore` reverts files, restores conversation, and **re-proposes the original tool call**. Per-tool-call undo — finer than a per-run worktree.
   - **Hooks** (docs/hooks): synchronous scripts at 11 lifecycle events — `SessionStart/End`, `BeforeAgent`, `AfterAgent` (can **force Retry or Halt**), `BeforeModel/AfterModel` (block/mock/redact), `BeforeToolSelection`, `BeforeTool` (block/rewrite args), `AfterTool` (block result/inject context), `PreCompress`, `Notification` — JSON-over-stdin/stdout with strict exit-code semantics. This is exactly where an external validation gate (like DevAgent's Compose checks) can be bolted onto a third-party worker CLI without forking it.
   - **Model routing**: `ModelAvailabilityService` auto-falls-back on quota/server failures (silent chain flash-lite→flash→pro for internal utility calls; prompts the user otherwise); optional **local Gemma model** makes routing decisions offline to cut cost/latency. The closest published analog to DevAgent's provider-failover problem.
4. **Deliver**: headless JSON envelopes carry token-usage stats; GitHub delivery happens through the Actions integration below.

**Isolation & sandbox**
- `--sandbox` / `GEMINI_SANDBOX=docker|podman|sandbox-exec|runsc|lxc` or `tools.sandbox` in settings. macOS Seatbelt profiles: `permissive-open` (default) confines writes to the project dir, allows network; `permissive-proxied` routes network through a proxy; `restrictive-*` and `strict-*` tighten reads/writes. Docker/Podman sandboxes run the `ghcr.io/google/gemini-cli:latest` image with the project mounted **at the same absolute path** as the host. Workspace trust is **fail-closed** in restricted modes with MCP-server filtering (v0.59.0); plus trusted-folders and a policy engine (docs/reference/policy-engine.md).

**Headless / CI worker mechanics** (docs/cli/headless.md, tutorials/automation.md)
- Non-TTY or `-p` triggers headless mode. `--output-format json` (one envelope: response + stats + error) or `stream-json` (NDJSON events: `init`, `message`, `tool_use`, `tool_result`, `error`, `result` with per-model token breakdowns). **Exit-code contract: 0 success, 1 general/API failure, 42 input error, 53 turn-limit exceeded** — a first-class watchdog signal DevAgent's loop driver could consume.
- CI recipes: pipe `git diff | gemini -p …`, bulk generation loops, `--output-format json | jq` extraction; CI auth must be non-interactive.

**Gemini CLI GitHub Actions** (github.com/google-github-actions/run-gemini-cli, beta 2025-08-06)
- The "assign a task, get a PR" model implemented inside GHA: a **dispatcher workflow** routes events to prebuilt workflows — **Issue Triage** (auto-label/prioritize, manual `/triage`), **PR Review** (auto-review on open, manual `@gemini-cli /review`), and **Gemini Assistant** (mention `@gemini-cli` in any issue/PR to delegate: "write tests for this", "fix this well defined bug"). Scheduled triggers supported (nightly). GEMINI.md per repo for conventions.
- Security posture: **Workload Identity Federation** (no long-lived keys), custom GitHub App identity with least privilege, command allowlisting, action version pinning, OpenTelemetry export of traces/metrics/logs to your own project. Outputs: `summary` + `error` action outputs; artifact upload optional.
- Google dogfoods it on the gemini-cli repo itself: issue triage on open/reopen (area/kind/priority labels, `status/need-information`, retesting flag for >6-versions-old reports), scheduled re-triage hourly, PR↔issue link sync every 15 min, 7-day auto-unassign of inactive assignees (docs/issue-and-pr-automation.md).

**Cost / metering**
- Per-user-per-day **model request** caps by auth method (docs/resources/quota-and-pricing.md): Code Assist individual 1,000; Google AI Pro 1,500; AI Ultra 2,000; free Gemini API key 250 (Flash only); Vertex pay-as-you-go varies; Workspace Code Assist Standard/Enterprise 1,500/2,000. Metering granularity is the inverse of Jules: requests, not tasks.

**What DevAgent can learn or steal**
- Exit-code contract incl. 42/53; streaming JSONL event schema; checkpoint shadow-repo with tool-call replay; AfterTool/AfterAgent hooks as the seam for external validators; model-routing table; WIF for CI credentials; the issue-triage → PR-review → mention-driven repair workflow set is essentially DevAgent's ticket→PR loop expressed as three copyable YAML files.

## Google Antigravity

**What it is / status (2026-09)**
- Launched 2025-11-18 as an "agent-first development platform" (public preview, free, alongside Gemini 3): an Editor surface (IDE) + an asynchronous **Agent Manager / "Mission Control"** surface where multiple agents run across workspaces in parallel. **2026 status: the product family is Antigravity 2.0** — a **standalone desktop agent command center** (macOS/Windows/Linux, no IDE dependency) plus **Antigravity IDE**, **Antigravity CLI**, and an **Antigravity SDK** (Python) for programmatic agents/tools/MCP/tasks (docs/overview, llms.txt product directory). Release 2.12.2 dated 2026-09-03 (changelog: "Gemini 3.8 Flash using ADC in AGY Enterprise"); 2.12.0 (2026-09-02) added `/boost`; 2.9.1 (2026-08-20) shipped **Remote Control**.
- Model access (pricing page): Gemini 3.8/3.7/3.6 Flash, Gemini 3.1 Pro, **Claude Sonnet & Opus 4.6, gpt-oss-120b** — multi-vendor model menu inside a Google product. Enterprise access via Google Cloud (Gemini Enterprise Agent Platform, consumption-based pricing).

**Workflow pipeline (stage by stage)**
1. **Project setup**: agents work in **Projects** — one or more folders/repos, with **native Git worktree support** ("agents operate in isolated background folders"), scoped settings/permissions (presets: Default / Full machine / Unrestricted), and multi-folder access for cross-repo context. Conversations outside projects run in an isolated scratch folder.
2. **Task intake**: prompt + **Mode choice — Local Mode (agent works in your folders) vs New Worktree Mode (isolated git worktree)** (docs/getting-started). Slash commands set autonomy: `/goal` = "run until the task is completely finished, not asking for intermediate input"; `/grill-me` = interrogate the user to refine the plan before implementing; `/schedule` = one-shot or recurring timed agent messages (Scheduled Tasks, run on Gemini 3.8 Flash).
3. **Planning Mode → Artifacts**: agent researches, then produces structured deliverables — task lists, **Implementation Plans**, task lists grouped in task groups; **Artifact Review Policy** per conversation: **Request Review** (agent halts at plan and diff milestones, inline comments steer it, then Proceed/Review) vs **Always Proceed** (fully autonomous). Fast Mode skips planning for small tasks.
4. **Execute**: file edits, terminal commands (interactive approval by default; "Yes / always allow for this conversation / persist to settings.json / No" prompt shapes), **browser subagent** (`/browser`; separate Chrome profile, URL allowlist/denylist, screenshots and **webm recordings**, Chrome DevTools MCP integration) — the "verify with browser + terminal" loop; agent-edit-scoped diffs in a Git-native VCS panel (agent edits vs working tree vs branch diffs; commit/push with generated messages). Voice transcription for prompts/artifact comments.
5. **Async subagents**: parent calls `invoke_subagent`; workspace modes `inherit` / `branch` (**isolated git worktree**) / `share`; clean context slate (no history inheritance); states Running/Idle/Killed, **auto-wake on message**, automatic worktree cleanup on kill, JSONL transcripts kept; **nesting depth limit: 10**; permissions and sandbox settings inherited, with approval requests **bubbling up** to the parent UI. Custom agents are `.md`+YAML (tools allowlist, per-agent model tier, `commandExecutionPolicy: sandbox`, skills/MCP). Built-ins: `research`, `browser`, `self`.
6. **Verification tiers**:
   - Default: single-pass tool checks + walkthrough artifact (summary of changes, with screenshots/recordings for browser work) at completion.
   - **`/boost`** (paid): three-phase pipeline — Orchestrator decomposes → parallel implementation/investigation workstreams in **ephemeral isolated worktrees** with local build/test validation → synthesis with full-suite regression; **failed assertions loop back for automated correction**.
   - **`/teamwork-preview`** (paid): Sentinel (coordinator, spawns the final Success Auditor) → Project Orchestrator (milestone decomposition, parallel tracks, **hands off to a fresh successor between milestones to prevent context degradation**) → read-only Explorers + Workers in non-overlapping tracks → **adversarial verification gates: Critic (independent review), Challenger (adversarial test suites, edge cases, failure-path probes), Auditor (checks test evidence against real command output — explicitly catches mocked/skipped tests), Success Auditor (full end-to-end pass before Sentinel returns the project)**. A Phase-1 scoping interview produces a reviewable prompt artifact with testable acceptance criteria and an **integrity mode** (`development` / `demo` / `benchmark`) that forbids escalating shortcut classes (mocked passes, reading test source to reverse-engineer expectations, copying core logic, non-stdlib). Exclusive file ownership per worker prevents sibling collisions; state lives in plan/progress artifacts, not chat.
7. **Self-improvement**: knowledge base the agent reads from and contributes to (launch blog: snippets, derived architecture, successful step sequences).

**Isolation & sandbox**
- **Terminal Sandbox** (docs/sandbox): OS primitives only — Linux namespaces / macOS Seatbelt (SBPL). Sandboxed commands write to project folders/temp/build caches, read /usr and /etc, block `~/.ssh` and `.env`, hide unmounted paths, and get **network only to domains approved via `read_url` permissions**. `unsandboxed(...)` allow rules are the explicit escape hatch (auto-recorded when a user approves a sandbox bypass — the prompt shows "🔓 Allow sandbox bypass…"). Security presets bundle terminal auto-execution × outside-folder access. Per-project overrides and per-subagent `commandExecutionPolicy: sandbox`.
- **Remote Control** (2.9.1+): drive/monitor desktop agent sessions from any browser, keep local filesystem/toolchain/credentials/worktrees, push notifications for completions and approvals — the "phone as approval surface" pattern.

**Human gates & approval UX**
- Per-conversation mode (Planning vs Fast) + artifact review policy (Request Review vs Always Proceed) = a tunable gate; interactive terminal approvals by default with persist-to-settings rules; permission bubbling from subagents; browser push notifications via Remote Control; `/grill-me` for up-front clarification; `/goal` for gate-free run-to-completion.

**Cost model / metering**
- **Work-correlated rate limits**: "rate limits are correlated with the amount of work done by the agent" (docs/plans) — i.e., token/compute-weighted, not per-message; free tier weekly refresh, Pro/Ultra **every-5-hour refresh** plus weekly caps; overage via purchasable **AI credits** at consumption pricing with a Never/Always setting; per-model quota visible in settings. **Explicitly no BYO-key/BYO-endpoint** and no contract org tiers yet.

**What DevAgent can learn or steal**
- The **Auditor's anti-mocked-tests check** ("validates work against real command output, ensuring tests genuinely passed rather than being mocked or skipped") is the published, productized version of DevAgent's evidence-attached-per-PR claim — DevAgent should extend its validation reports to cross-check test evidence against raw command output and out-of-band verification, or the moat claim narrows to backend-domain gates only.
- **Integrity modes** (`development/demo/benchmark`) = a per-ticket knob for how much shortcut-taking is tolerated — maps cleanly onto DevAgent's PO/plan inputs.
- **Exclusive file ownership per worker** and **orchestrator-successor handoff** are directly reusable mechanisms for DevAgent's multi-worker dispatch and long-horizon context hygiene.
- Worktree-per-agent is now table stakes (Antigravity 2.0, Gemini CLI, Claude Code, DevAgent all do it) — isolation is no longer a differentiator; gates are.
- `/goal` + `/grill-me` show the industry converging on "autonomy dial + up-front clarification interview," which DevAgent's plan-gate should offer as modes, not just a fixed step.

## Gemini Code Assist / GitHub integration (brief)

- **Code Assist on GitHub** (Standard/Enterprise; docs.cloud.google.com/gemini/docs/code-review, updated 2026-09-03): a GitHub app that acts as an **automated PR reviewer** — auto-summarizes PRs, in-depth reviews, `/gemini` comment tag for Q&A in the PR context; auto-retrieves repo + PR info. Enterprise (Preview): 100+ PR reviews/day quota, per-repo or cross-repo style guides, GHES support, Developer Connect wiring (pinned to us-east1). **Never touches `.github/workflows/` files** — explicit workflow-injection defense. Review-only: it does not author PRs (that's Jules / GHA).
- **Agent Mode in IDEs** = Gemini CLI embedded in VS Code (Preview) / IntelliJ (stable): plan → review/edit/approve → auto-approve mode with rollback (2025-08-21). Shared quota pool with Gemini CLI (1,500–2,000 req/day on paid tiers).
- Structural takeaway: Google deliberately splits the SDLC across products with different quotas — Jules (tasks/day, author+fixer), Code Assist (PR reviews/day, reviewer), Gemini CLI/GHA (requests/day, automaton). No single Google product yet matches DevAgent's ticket→validated-PR→evidence loop end to end; the closest is Jules + CI Fixer.

## Cluster synthesis

- **Shared pattern**: every Google surface now has (a) an explicit **plan artifact with a review-or-auto-proceed policy**, (b) **ephemeral isolated compute** per work unit (Jules VM, gemini-cli Docker/Seatbelt sandbox, Antigravity worktrees), (c) **structured, replayable event logs** (Jules activities API, Antigravity artifacts + JSONL, gemini-cli stream-json), and (d) a **closed external-feedback loop** (Jules CI Fixer + Render fixer, `@gemini-cli` mentions, gemini-cli AfterAgent retry hooks). DevAgent's ledger/worktree/evidence design is directionally aligned with where the market went — the differentiation must now come from gate depth, not from having these primitives.
- **The verifier is being productized**: Jules ships a Planning Critic (−9.5% failures, vendor claim) and a code Critic; Antigravity ships Critic/Challenger/**Auditor-that-catches-mocked-tests**/Success Auditor with integrity modes. DevAgent's "validation depth" moat survives only where these generic verifiers don't reach: migration safety (shadow-DB replay, Squawk-style lint), FK integrity, async/race review — and by adding evidence-vs-raw-output cross-checks before someone else does.
- **Human gates are disappearing behind LLM critics**: Jules auto-approves plans (timer, and API default) with a critic as compensation; Antigravity's Always Proceed exists; Gemini CLI has YOLO mode. The trend is exactly DevAgent's unattended-loop posture — but Google keeps the *merge* human, always.
- **Metering philosophies differ usefully**: Jules counts tasks, gemini-cli counts model requests, Antigravity counts *work done* on 5-hour windows with credit overage and refuses BYO-key. DevAgent's BYO-provider is genuinely unique here (and Antigravity's explicit "no BYO-key" is a marketing gift).
- **Isolation is converging on OS-native sandboxing + git worktrees** (Antigravity namespaces/Seatbelt, gemini-cli Seatbelt profiles/Docker, DevAgent Compose+worktrees); only Jules still runs fat per-task cloud VMs with full internet — and gets the security caveats to match.
- **Proactivity is now an evaluated research direction** (arXiv 2605.06717: revert-to-pre-fix ground truth, exploration budgets, Hit@K judging of "insight policies"). DevAgent's scout/PO backlog has no equivalent measurement; the paper's methodology is cheap to adopt as an internal eval for the selfbuild loop.
