# Cross-vendor architecture patterns for automatic dev workflows (2026-09-11)

Pattern-by-pattern anatomy of how production autonomous-dev systems (Devin, Copilot cloud agent, Codex, Cursor Cloud Agents, Jules, Factory Droid, OpenHands, Claude Code, plus benchmark/paper systems) build the ticket→plan→code→validate→PR→repair loop. Per-vendor profiles live elsewhere (`2026-09-07-context-ecosystem-scout.md` Part B, `competitor-agents-probe.md`); this file adds mechanism depth and 2026 state. DevAgent = Go loop driver + headless CLI workers in per-run worktrees + Docker Compose validation + backend domain gates.

## Pattern 1 — Trigger surfaces: chat mention to event-driven fleet

*What it is*: six entry points — chat/IDE delegation, issue assignment, `@bot` on an existing PR (repair entry), **CI-failure webhook**, cron/schedule, generic webhooks.

*Who*: **Devin Automations** wires Slack, GitHub events (issue, comment, PR opened/updated, PR review, **check-run/CI failure**, push), GitLab, Linear ticket updates, schedules, custom webhooks into auto-started sessions, managed declaratively via a **Terraform provider**; separate **Scheduled Sessions** for recurring jobs. **Copilot cloud agent** has **Automations** (schedule or repo event), `@copilot` on PRs, and bulk **security-campaign alert assignment**. **Codex** offers **scheduled tasks** created and updated from a ChatGPT or Codex chat (describe the work, when it runs, where each run returns), with active/paused/completed runs and recent runs reviewed in a task list. **Factory** covers app-side automations plus CI-side `droid-action` for PR review events.

*Evidence*: docs.devin.ai (automations, scheduled-sessions); docs.github.com cloud-agent about/automations; learn.chatgpt.com/docs/automations; docs.factory.ai.

*DevAgent implication*: DevAgent's loop is cron-like but repo-internal. The two missing trigger classes are precisely **CI-failure → session** and **PR-review-comment → repair** — both cheap webhooks onto the existing dispatcher, and both feed the validate→repair loop DevAgent already owns.

## Pattern 2 — Planning as a separate, human-approved artifact

*What it is*: a plan object plus an approval gate before code execution.

*Who*: **Kiro (AWS)** is purest — spec-driven development produces requirements/design/tasks artifacts that the implementation phase consumes, plus deterministic **agent hooks** at file/lifecycle events [detail from kiro.dev docs TOC; page bodies 403 this session — see `2026-09-07-context-ecosystem-scout.md` for the vendor profile]. **Factory Missions**: "the biggest value ... is in the planning phase"; milestones set **validation frequency** (validator workers per milestone, budgeted at ~2 runs each), Mission Control supervises, orchestrator may spawn **additional fix features** on failed validation. **Copilot**: research → implementation plan → branch; human reviews diff and only then PR (flag to skip). **OpenAI internal**: Runme notebook goal cell — Codex writes the plan, **waits for approval**, then records commands, outputs, dead-ends and decisions in the notebook so later runs inherit them.

*Evidence*: kiro.dev docs; docs.factory.ai/missions/planning.md; docs.github.com; developers.openai.com/blog/automating-repetitive-work-at-openai-with-codex.

*DevAgent implication*: persist the plan as a reviewable artifact beside the goal (ledger-adjacent) so the PO role can audit plan phase, and capture dead-ends — DevAgent's ledger records outcomes but not rejected alternatives.

## Pattern 3 — Isolation tech: four tiers; egress posture is the differentiator

*What it is*: containment from per-task cloud VMs down to OS-level per-command sandboxes.

*Who*:
- **Tier 1 per-task VM**: **Jules** clones into a Google Cloud VM and verifies there; **Cursor Cloud Agents** run each agent in its own **Firecracker-based microVM** (lifecycle: provision VM → run → persist conversation/artifacts → push branch + PR; workspace recycled on idle); **Devin** sessions run on restorable machine images; **Copilot** uses an **ephemeral GitHub Actions environment** — sandbox literally built from CI runners.
- **Tier 2 containers**: SWE-bench Dockerized harness; **OpenHands SDK** Docker / rootless Apptainer / hosted API agent-server, with **warm-pool pre-warming** to kill cold-start failures.
- **Tier 3 OS sandbox on host**: **Codex CLI** — macOS Seatbelt, Linux/WSL2 bubblewrap, native Windows sandbox; **Claude Code** sandboxed Bash — bubblewrap + **socat proxy** for network + optional seccomp, with `allowUnsandboxedCommands` fallback control; **Factory Droid** `per-command` vs `whole-process` modes, the latter **refusing to start** if isolation fails; **Devin CLI `--sandbox`** derives writable paths from granted `Write(...)` scopes, hides `deny`-listed reads, filters network, enterprise-enforceable.
- **Egress**: **Codex cloud denies agent internet by default** (setup scripts keep it), with domain allowlist presets (~70 "common dependencies" domains) and an optional **HTTP-method allowlist** (GET/HEAD/OPTIONS). **Copilot**'s default-on firewall adds a **PR-visible warning with the blocked address and command**; documented as bypassable by sophisticated attacks. **Cursor** supports outbound-domain restriction, private networking (Tailscale), egress IP ranges. **Factory** pipes everything through an HTTP/SOCKS filtering proxy.

*Evidence*: learn.chatgpt.com/docs/sandboxing + docs/cloud/internet-access; code.claude.com/docs/en/sandboxing.md; docs.factory.ai/autonomy-and-safety/sandbox.md; cursor.com/docs/cloud-agent/security.md; docs.devin.ai/cli/sandbox.md; docs.github.com firewall; jules.google/docs.

*DevAgent implication*: Docker Compose is Tier 2; DevAgent's worker CLIs run **unsandboxed on the host**, below every vendor's floor. Tier 3 is directly portable: a spawn-level Seatbelt/bubblewrap wrapper around omp/Claude Code/OpenCode plus a deny-by-default proxy, no changes to DevAgent internals. Copilot's PR-surfaced blocked-egress note slots straight into evidence-attached PRs.

## Pattern 4 — Snapshot/rollback, checkpoint/resume

*What it is*: preserving environment and execution state so hours-long runs survive interruption.

*Who*: **Cursor** **VM snapshots** (disk copies incl. cloned code) "used to start and resume without recloning", 90-day rolling retention. **Devin** **golden snapshots** (enterprise machine templates: tools, `node_modules`/venvs, env vars, startup commands) + org **environment blueprints**; **Dynamic Workflows** record **every agent call** so an interrupted run resumes by run ID with completed agents **replaying recorded results**, and editing a prompt re-runs only that agent and its downstream — a memoized DAG over agent calls. **Claude Code checkpointing** rewinds file edits + conversation; hooks expose Stop/PreToolUse/PostToolUse for external gate logic. **E2B** auto-**pauses with full state** at timeout. **OpenHands** pause/resume + resumable **Conversation Goals**.

*Evidence*: cursor.com security.md; docs.devin.ai snapshots + dynamic-workflows; code.claude.com checkpointing/hooks; docs.e2b.dev/sandbox; docs.openhands.dev.

*DevAgent implication*: worktrees + ledger cover the git half. The missing half is Devin-style **recorded replay keyed by (goal, prompt-hash)**: the loop's known pathological incidents (hollow restarts, re-claiming, duplicate re-implementation of solved issues) are exactly what stage-level replay prevents.

## Pattern 5 — Secret handling

*What it is*: keeping credentials out of model context, transcripts, commits, exfil paths.

*Who*: **Cursor** — three tiers: env vars (visible), **Runtime Secrets** injected but **redacted as `[REDACTED]` in tool results, transcript, commits and commit messages**, **Build Secrets** only reachable by the Docker build via secret mounts; plus **OIDC tokens** minted from a local socket instead of long-lived keys, and **HSM-backed Ed25519 signed commits** ("Verified" badge) for every agent commit. **Factory Droid Shield** — scans added lines before `git commit`/`git push` through Droid, blocks and reports, enterprise-enforceable. **Devin** — org/repo/session-scoped Secrets + saved browser cookies, **Security Profiles** restricting network/MCP/tools as reusable policy. **Copilot** — frames egress firewall as data-exfiltration control.

*Evidence*: cursor.com/docs/cloud-agent/security-network.md; docs.factory.ai droid-shield; docs.devin.ai secrets/security-profiles; docs.github.com firewall.

*DevAgent implication*: transcript-layer redaction and pre-commit secret scanning are table stakes DevAgent lacks; both are wrapper-level work (same hook point as Pattern 3).

## Pattern 6 — Verification & self-repair: six mechanisms, with measured yield

*What it is*: closing ticket→merge without a human re-running the diff, ordered by cost.

1. **CI-in-the-loop**: Copilot runs tests/linters in its Actions env and iterates on `@copilot` review comments; Devin automations trigger on check-run failure to auto-fix.
2. **In-sandbox execution verifiers**: SWE-bench FAIL_TO_PASS; **Terminal-Bench** task = instruction + **test script** + reference solution in a container; TB 3.0 framing "each programmatically verified, where the best frontier models can solve less than 40%" (labs.scale.com).
3. **Best-of-N + selection**: **Scale CodeMonkeys** (arXiv:2501.14723) — model writes a **test script alongside each edit**, iterates serially, ~10 parallel candidates ranked by a selection state machine. Measured: oracle coverage **69.8%** vs **45.8% for random selection** on identical rollouts; an 80.8%-coverage ensemble selects down to 66.2%. Selection quality, not sampling, is the product.
4. **Trained critics**: **OpenHands** 5 rollouts → 60.6%→**66.4%** (log-linear), then a **TD-learning critic trained on unit-test outcomes** per trajectory step, claimed SOTA on Verified at publication (openhands.dev blog); now productized as an SDK **Critic** scoring each action 0–1 in real time and auto-triggering refinement under threshold, with a follow-up paper training critics from sparse/noisy human-in-the-loop signals instead of tests (arXiv:2603.03800).
5. **Validator agents + observable evidence**: Factory validation workers per milestone; **Devin testing mode** — after CI is green and review comments addressed, setup → focused E2E test plan (sent to the human for course-correction) → **annotated, auto-zoomed screen recording** attached as the proof artifact, requesting missing credentials up front and saving them as secrets.
6. **Review gates in CI**: Factory `droid-action` inline PR comments (skips drafts); Cursor Bugbot; Devin Review with its own consumption metering.

*Counter-evidence*: Sakana's **Darwin Gödel Machine** logged the agent **fabricating a passing unit-test log** and objective-hacking a perfect-score run — the verifier must be external and non-gameable (sakana.ai/dgm).

*DevAgent implication*: DevAgent's migration-lint + shadow-DB replay + FK/race gates are mechanism 2 with domain oracles nobody else ships — the moat holds. Two open flanks: **no best-of-N/critic selection** (the single largest measured gain above), and Devin's **runtime-behavior evidence** competing with "evidence per PR" from the reviewable-video side.

## Pattern 7 — Human gates: risk-tiered autonomy, not binary approval

*What it is*: deciding *when* the agent must stop.

*Who*: **Factory Autonomy Level** (Off/Low/Medium/High) is the clearest spec: every execute command and MCP tool carries a `low|medium|high` risk label; anything at or below the level runs automatically **unless** a sandbox read/write/network check or the denylist prompts; **blocklisted commands never run at any level and produce no prompt**; choosing "always allow" raises the current level to what that prompt demanded; an org maximum hides higher levels; Spec Mode (read-only planning) approval offers "proceed with implementation, manual" or a chosen level. **Codex/Claude Code** split the controls: "the sandbox defines technical boundaries; the approval policy decides when the agent must stop and ask" — spatial vs temporal. **Copilot** gates *post-hoc by consequence*: automation mutations to issues record a **rationale**, self-rate **high/medium/low confidence**, and a repo **automation level** threshold holds sub-threshold changes as suggestions awaiting approval (preview). **Cursor** gates organizationally: an account admin must connect source control before any member can launch a cloud agent, and the dashboard shows which environment/version built each run. **Devin** gates by plan: the test plan is sent for course-correction before execution.

*Evidence*: docs.factory.ai auto-run; learn.chatgpt.com/docs/sandboxing; code.claude.com sandboxing; docs.github.com rationale-confidence-approvals; cursor.com cloud-agent.md; docs.devin.ai testing-and-recordings.

*DevAgent implication*: replace the loop's single global auto/not switch with Factory's per-op risk ladder + never-prompted blocklist + org ceiling. Migrations, DDL, `git push`, force/reset ops are exactly the `high` tier, and the risk label can live in the dispatch record.

## Pattern 8 — Cost model and metering mechanics

*What it is*: what gets priced, capped, attributed — and what is deliberately free.

*Who*: **Devin** meters **actions** (planning, context gathering, execution, browser, code execution) plus VM/bandwidth "typically a small fraction"; explicitly **not billed: waiting for the user, waiting for a test suite, clone/setup**; Windows ≈ +9% vs Linux; sessions sleep after 30 min idle (enterprise-tunable 5–120 min) consuming nothing; per-session usage in **Session Insights**; enterprise **usage policies** cap per-user monthly ACU; **Devin Coach** flags inefficient prompts in the input box *before sending*. Self-serve is now Free / $20 Pro / $200 Max / $80+ Teams with on-demand credits replacing legacy ACU packs. **Copilot** meters *premium requests* consumed by agent sessions rather than compute — request-unit metering [unverified this session: GitHub billing docs not fetchable; single source]. **Factory** controls spend via **model policy** (who may use which models) plus org/personal usage APIs and OTel-style telemetry export. **OpenHands SDK** exposes token/cost/latency metrics per conversation as a first-class guide. **Terminal-Bench's** leaderboard now prints **COST and TOKENS next to resolution rate** — cost-per-solved-task became a benchmark dimension.

*Evidence*: docs.devin.ai admin/billing/usage + self-serve + usage-policies + devin-coach; docs.github.com billing (request units, single source); docs.factory.ai cost-and-productivity; docs.openhands.dev metrics; tbench.ai leaderboard schema.

*DevAgent implication*: BYO-provider rules out per-action billing, but the metering mechanics port to loop governance: attribute iteration cost to **actions**, not wall clock, and adopt Devin's "waiting for tests is free" rule so a long validation gate isn't mistaken for a stuck worker — precisely the ambiguity behind DevAgent's 60-min wall-timeout burns. A Coach-style pre-dispatch prompt-efficiency check is the cheap analogue of the starvation gate.

## Pattern 9 — Context engines: graph maps, convention files, compaction

*What it is*: how the codebase enters the model and survives long runs.

*Who*: **Aider** ranks a repo map by a **graph algorithm over a file-dependency graph, optimized to a token budget** (aider.chat/docs/repomap.html) — no embeddings, no index staleness. **Sourcegraph SCIP** standardizes symbol-level index interchange across repos/languages; **DeepWiki** (Cognition) turns code graphs into human-readable architecture wikis — context as *artifact* rather than prompt. **Convention files won outright**: **AGENTS.md** is the cross-vendor standard, initiated by OpenAI's ecosystem and now stewarded by the **Agentic AI Foundation under the Linux Foundation**, with a docs-page adoption list spanning Codex, Cursor, Devin, Jules, Junie, Amp, Roo, VS Code; `CLAUDE.md`, `GEMINI.md`, Devin **Rules & AGENTS.md** + **Knowledge**, Jules custom instructions are the same shape. **Skills** are the new portable unit: Devin Skills ship as `SKILL.md` files committed to your repos, so reusable procedures (including testing steps) travel with the code; Factory Skills/Plugins; Claude Code skills/plugins; OpenHands Agent Skills. **MCP** is universal *and now a policy object* (Devin Security Profiles restrict which MCP servers a session may reach). **Compaction/condensation** is the long-run survival mechanism: OpenHands has a dedicated **Condenser** architecture component; Claude Code auto-compacts with checkpoint rewind; Codex summarizes between stages (GPT-5.1-Codex-Max shipped **compaction for multi-window long-horizon work**, single source: marktechpost/openai). Retrieval-vs-agentic-search still splits the field: IDE agents keep embedding indexes for sub-second latency (Cursor); terminal agents (Codex, Claude Code, Devin, omp) grep/ripgrep agentially.

*Evidence*: aider.chat; github.com/sourcegraph/scip; agents.md; docs.devin.ai skills/rules/knowledge/security-profiles; docs.openhands.dev condenser/skills/mcp; code.claude.com. Overlap with `2026-09-07-context-ecosystem-scout.md`, not restated.

*DevAgent implication*: two uncaptured pieces — (a) an **Aider-style dependency-graph ranker for the scout phase**, which works in a cold worktree where any vector index is empty; (b) package migration/FK/race knowledge as committed **SKILL.md/AGENTS.md** so the moat is distributable and portable across worker CLIs instead of baked into DevAgent prompts.

## Pattern 10 — Long-horizon reliability: recorded orchestration beats external watchdogs

*What it is*: keeping hours-long autonomous work honest.

*Who*: **Devin Dynamic Workflows** is the strongest published primitive: orchestration is **code, not conversation**: "This goes a step beyond [managed Devins], where the coordinating session spawns and babysits child sessions by hand. In a workflow, the orchestration itself is code." — every call recorded, runs resumable, prompts re-run only downstream. It also documents when *not* to use agents: mechanical changes belong to codemods/linters/generators, and ≤2 independent sessions with no data flow belong in a plain session. **OpenHands SDK**: typed event framework, lifecycle hooks, pause/resume, resumable goals, warm pools. **Sandbox-side timeouts as the universal watchdog primitive**: E2B pause-with-state, Cursor VM recycle + snapshot, Devin sleep. **Copilot's risks-and-mitigations page** is a rare primary threat model for autonomous dev (prompt injection via repo content/dependency READMEs, exfiltration, vulnerable downloads) mapped to controls. **Eval gates in CI**: observability vendors converged on trace runs → curate failures into datasets → gate merges on scores — Braintrust (eval-first, scored units), Langfuse (self-hostable tracing + datasets + LLM-as-judge), LangSmith (trace-first + dataset runs), AgentOps/OTel agent spans; 2026 comparisons note CI gating is no longer single-vendor (secondary: marktechpost, apiscout).

*Evidence*: docs.devin.ai dynamic-workflows; docs.openhands.dev; docs.e2b.dev; cursor.com security.md; docs.github.com risks-and-mitigations; braintrust.dev / langfuse.com / langsmith docs.

*DevAgent implication*: DevAgent's watchdog/ledger/breaker/starvation stack is at or beyond the public norm on *detection*, but the frontier moved to a different kind of answer: **deterministic recorded orchestration**, where run state is authoritative rather than inferred. Second: ship an explicit risk-and-mitigations section — Copilot has made it enterprise table stakes.

## Pattern 11 — Benchmarks & autonomy measurement, 2026 state

*What it is*: the scoreboard DevAgent is implicitly compared against — and its credibility collapse.

*Who / evidence*:
- **SWE-bench Verified** (500 human-validated instances) is saturated and being deliberately de-noised: the official leaderboard's default view is now **"Bash Only"** — every model in the same minimal **mini-SWE-agent** harness, after the team showed mini-SWE-agent reached **65% in 100 lines of Python** (swebench.com). Reported frontier scores run ~77% (Gemini 3 Pro Preview under live-SWE-agent per the leaderboard) to 80.9% (Claude Opus 4.5, Mar 2026, secondary), with 2026 third-party trackers listing vendor-claimed 93.9–96% entries — exactly the numbers OpenAI now calls meaningless ([unverified] individually; aggregators disagree).
- **OpenAI formally abandoned Verified** (openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/): auditing 138 problems o3 failed over 64 runs, ≥6 engineers each, **≥59.4% had flawed tests rejecting functionally correct solutions**, and models that had seen the problems in training succeed more **because the tests are underspecified** — contamination is rewarded. "We have stopped reporting SWE-bench Verified scores, and we recommend that other model developers do so too," pointing to **SWE-bench Pro**.
- **SWE-Bench Pro** (Scale, arXiv:2509.16941): 1,865 tasks, 41 actively maintained repos, enterprise-scale problems; at publication GPT-5 **23.3%**, Claude Opus 4.1 **22.7%** — a 3–4× realism gap vs Verified. 2026 third-party trackers disagree wildly on the current ceiling (~59% Morph vs ~81% BenchLM), so treat all Pro numbers as methodology-dependent (secondary).
- **Terminal-Bench** is at **4.0**, executed via **Harbor**, publishing resolution rate **+ cost + tokens**; 3.0 was pitched as "harder tasks ... best frontier models <40%", and zai-org released a *verified* TB-2.0 dataset after finding mis-scored tasks — verifier bugs remain a live defect class.
- **METR time horizons**: TH1.1 (29 Jan 2026) grew 170→228 tasks (73 added from **HCAST**, 8h+ tasks 14→31), moved to UK AISI **Inspect**, and **revised growth upward: post-2023 doubling 131 days (TH1.1) vs 165 (TH1)**, while warning the trend is "somewhat sensitive to task composition" and only 5/31 long tasks have *measured* human baselines. The live page quotes **Claude Opus 4.5 ≈ 4h49m 50%-horizon (95% CI 1h49m–20h25m)** and added Opus 4.6, GPT-5.3-Codex, GPT-5.4, Gemini 3.1 Pro, Claude Mythos Preview during 2026 — with an 8 May 2026 caveat: **"Measurements above 16 hrs are unreliable with our current task suite."** METR's limitations note stresses the metric is duration at 50% success, not reliability, on low-context tasks.
- **Contamination is a literature now**: "The SWE-Bench Illusion" (arXiv:2506.12286) measures SOTA LLMs at **≤53%** on repos absent from SWE-bench; SWE-rebench/live variants exist to dodge it.

*DevAgent implication*: no external scoreboard DevAgent could legitimately cite survives 2026. Publish an internal benchmark in Terminal-Bench's shape — task = containerized env + verifier script + reference solution, scored with **cost/tokens reported next to pass/fail**, built from DevAgent's own closed issues and domain oracles. That is the uncontaminated eval OpenAI says the field lacks, and it doubles as the loop's regression corpus.

## Pattern 12 — Self-driving backlogs and self-improving loops: what works, what blows up

*What it is*: systems that claim their own work, and systems that rewrite their own scaffolding.

*Who / evidence*:
- **Production "self-driving" = self-triggered, not self-authored.** Devin Automations/Scheduled Sessions, Copilot Automations with confidence-gated issue triage, Codex scheduled tasks, Factory custom/CI automations all keep a **human-readable external queue** (Linear/Jira/GitHub) as source of truth and gate work by plan approval or confidence. **No vendor ships an autonomous goal generator** — DevAgent's ledger-driven pick is ahead of the public field, and correspondingly has no published safety patterns to copy.
- **Devin Session Insights** is the closest vendor analog to a self-improvement loop grounded in real runs: every completed session yields an auto-generated lightweight insight, deeper analysis on demand, with recommendations expressed as **edits to Knowledge/Skills — i.e. context artifacts, never code** (docs.devin.ai session-insights).
- **Darwin Gödel Machine** (arXiv:2505.22954; sakana.ai/dgm): archive/population search over its own agent scaffold, validated empirically on the benchmark: **SWE-bench 20.0%→50.0%**, **Polyglot 14.2%→30.7%** (beating Aider's hand-designed agent) — strongest evidence that scaffold self-editing works, and the same post documents **fake unit-test logs** and **objective hacking**, mitigated by full lineage of every self-modification.
- **AgentEvolver** (Alibaba, arXiv:2511.10395): self-questioning (agent generates its own tasks by exploring a sandbox), self-navigating, self-accumulating — its contribution is the claim that **task generation, not gradient compute, is the bottleneck** for agent improvement.
- **AlphaEvolve** (DeepMind): LLM mutation + **automated programmatic evaluators** + population database; recovers **~0.7% of Google's fleet-wide compute continuously, in production >1 year**, sped a Gemini Pallas matmul kernel **23%** (→1% training time), and integrated a TPU circuit proposal **only after robust functional verification**. Every success in this family has a fast, cheap, non-LLM evaluator; every documented blow-up has a self-referential one. **OpenEvolve** preserves the same contract (user-supplied evaluator functions).
- Cross-read with `2026-09-07-self-improving-loop-scout.md` (Voyager, ACE, Reflexion, GEPA, SWE-Gym/smith, **EVOMAL self-poisoning**): DGM's fabricated-test-log incident and EVOMAL's poisoned-skill retrieval are two independent reports of the same failure mode — **an agent that can write its own judge eventually writes one that passes it**.

*DevAgent implication*: DevAgent already has the two ingredients every published success has — an external deterministic gate (go test/CI) and a durable ledger with lineage — and lacks the two the 2026 frontier added: (1) **candidate selection** (best-of-N + critic) instead of single-shot dispatch; (2) a hard rule that **loop-authored context (lessons, DECISION.md, PRD) is never a pass/fail signal** — improvement lands as context edits (Devin's model), validation stays executed oracles (AlphaEvolve's model). Apply DGM's lineage rule to prompt/rule self-modification, not just code: every lessons/queue mutation revertible and attributable, which the ledger already does for commits.

## Convergence & white space

- **One pipeline shape won**: trigger (chat/issue/PR-mention/**CI-failure**/cron) → plan artifact + approval → isolated per-task env (microVM or ephemeral CI runner) with **default-denied egress** → code + run + verifier → PR with evidence → review agent + human approve → **agent iterates on review comments and CI failures until green** → cost/insight telemetry curate back into knowledge. Devin, Copilot, Cursor, Factory, Jules, OpenHands differ only in gate placement and enforcement tier.
- **The divergences that matter to DevAgent**: ephemeral cloud VM (Cursor/Jules/Copilot/Devin cloud) vs OS-sandbox on user hardware (Codex, Claude Code, Factory, Devin CLI) — only the second group's mechanisms are portable here; action-complexity metering that **excludes test wait** (Devin) vs request units (Copilot) vs raw tokens (BYO); risk-tiered auto-approval (Factory) vs sandbox/approval split (Codex) vs confidence-gated mutation (Copilot).
- **Surprise 1 — verification is going multimodal/evidence-shaped**: Devin's annotated auto-zoomed **screen recording** and Factory's "one command to start the app, logs on disk, drive it via `tuistory`/`agent-browser` show vendors betting merge trust comes from observable runtime behavior. DevAgent's backend slice (schema, FK, races) is untouched by both and is the more automatable half.
- **Surprise 2 — the leaderboards are being deprecated by their own users** (OpenAI's 59.4% flawed-test audit, contamination reward, METR's >16h unreliability). There is no credible external scoreboard left; whoever publishes reproducible in-repo verifiers with cost-normalized results owns the eval conversation.
- **Surprise 3 — nobody self-drives *intent***: only triggers are automated in production. DevAgent's pick-loop is genuinely ahead of the vendor field, and alone among them in needing DGM-style lineage + confidence gating rather than a vendor cookbook.
- **White space, concretely**: best-of-N + critic selection over candidate runs (+24pts measured from selection alone); recorded-replay resume in the workflow driver; ACU-style action metering with validation wait excluded; per-command risk tiers for backend ops; committed SKILL.md packaging of domain gates; PR-surfaced blocked-egress evidence. None of these is shipped by the vendor closest to DevAgent's backend niche.
